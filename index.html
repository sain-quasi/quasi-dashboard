Lead time & reorder settings — per SKU
Packaging + production + shipping = total lead time. Reorder-by = projected stockout date − lead time. Safety stock is an explicit buffer per SKU.
Seasonality multiplier
Monthly multiplier on the current run rate. It is applied to every projected date — days of supply, projected stockout, reorder-by, suggested order and the forecast calendar — so the tool plans against the same demand you do. 1.0 = flat demand.
Connected data sources
How the team sees today's numbers. Sales history comes only from the Orders files you upload — the old Google Sheet is no longer read.
🔴 Team link (shared snapshot)
A small Google Apps Script keeps the published snapshot in a Google Sheet you own. The sheet can be brand new and empty — it needs no tabs — and it is never made public.
ℹ️
One-time setup: create a new Google Sheet → Extensions → Apps Script, paste quasi-apps-script.gs (v4), then Deploy → New deployment → Web app (Execute as: Me, Who has access: Anyone). Copy the URL ending in /exec, paste it below, and press Connect. Then press Copy team link and send it to the team once.
📤 Publish today's data for the team
Publishing happens automatically right after you upload your Shopify/Amazon files — anyone who opens the dashboard link then sees the same numbers, with nothing to upload or click. The button re-publishes manually. Requires the live connection above.
Send this once in Slack — it carries the connection, so teammates set nothing up.
Amazon mapping — by ASIN
Each Amazon product (ASIN) is mapped to one Quasi SKU; every seller SKU under that ASIN follows it. Matching never relies on the text of the seller SKU. An unmapped ASIN is not counted anywhere.
Planned supply freezes
Known windows where China production stops entirely (e.g. Chinese New Year) — the Forecasting tab won't suggest placing an order during one, and pulls it earlier instead.
Data handling
This dashboard saves your last upload in this browser so it can be reopened without re-uploading. Nothing is sent anywhere else.
